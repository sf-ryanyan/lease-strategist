# X1 — 总控台（多物业管理 + 到期提醒）

**用量**：🟢 · **触发**：「今天 / 这周做什么」「看板」「总控台」「XX 地址到哪一步了」「申请人对比」；每次对话第一次打开 skill 时做一次提醒检查。

## 1. 文件夹结构（有文件夹时）

```
租管数据/
  设置.md                    ← M00 设置卡片
  总控台.xlsx                ← 所有物业的表（模板在 skill 的 dashboard/ 里）
  法规缓存/{城市}.md          ← X3 核实过的本地规定 + 核实日期
  物业/{地址简写}/
    记录.md                  ← 按日期追加的工作记录和发出的消息
    01-合同租约/  02-披露/  03-筛选/  04-照片/
    05-维修/      06-通知/  07-保险/  08-沟通/
```

- **第一次用**：把 skill 里的 `dashboard/dashboard-template.xlsx` 复制为 `租管数据/总控台.xlsx`。模板的数据表是空的（示例只在「使用说明」页），**从第 2 行开始写**。不要用 `delete_rows` 删行（会弄乱下拉选项和公式）。
- **物业编号**：P001、P002……按顺序编；用户说「P1」就对应 P001。
- **地址简写**：门牌号 + 街名 + 城市，例如 `123-main-st-sanjose`。还不知道地址时用 `{物业编号}-{城市}`（例如 `p002-sanjose`），知道后改名。
- **隐私**：只存联系方式和业务信息。不存 SSN、出生日期、证件号、银行或卡号、信用报告原件、证件照；不记申请人或看房人的家庭、孩子、动物、住房券等信息。筛选材料留在筛选平台，这里只记结果和理由。文件至少保存 3 年。

## 2. 怎么读写 Excel（省 token、不出错）

**读**
- 只读需要的那张表；用 `openpyxl` 的 `read_only=True, data_only=True`，按行取值（`values_only`）。
- **遇到第一列为空的行就停**（模板的公式预填到第 200 行，空行不要读）。
- 按物业编号筛选，只把需要的几行放进对话。不要打印整个文件。
- **天数和日期自己算**：已上市天数、下次调价检查日、逾期状态等带 `TODAY()` 的结果，保存后会过期。读的时候用表里的原始日期（上市日期、到期日、报修日期等）在 Python 里按今天重新算，不要相信文件里存的计算结果。

**写**
- 只改需要的单元格；**不要改带公式的列**（表头写了「自动」的列）。
- 写完后，能重算就重算一次（用 LibreOffice 等工具）；不能重算也没关系，因为读的时候会按原始日期重新计算。
- 有下拉选项的列只填选项里的值；未知就填「未知」（有这个选项时）或留空。
- 不能运行代码时：输出要新增或修改的行（表名 + 列 + 值），请用户自己粘贴。

## 3. 总控台的 11 张表

| 表 | 主要列（「自动」= 公式列） |
|---|---|
| **使用说明** | 用法、设置摘要、**提醒天数**（续约 90/60/30 的数字在这里改，租约表的提醒日会跟着变）、状态代码、每张表的示例 |
| **物业总览** | 物业编号、地址、城市、类型、业主、服务类型、**租金流向（A/B）、维修付款（业主直付 / 信托 / C 租客垫付）、审批上限**、当前步骤、状态、月租金、上市日期、已上市天数（自动）、下次调价检查日（自动）、下一步、截止日、更新日期 |
| **联系人** | 物业编号、角色（业主 / 租客 / 紧急联系人 / 业主代理人 / HOA）、姓名、电话、邮箱、通讯地址、语言、备注 |
| **租约** | 物业编号、租客、起租日、到期日、类型（定期 / 月租）、月租金、交租日、宽限期天数、滞纳金、押金、押金保管、AB 1482（适用 / 豁免(有声明) / 豁免(缺声明) / 未知）、本地租控、定期检查条款、**责任分工**（草坪 / 空调滤网 / 虫害 / 家电 / 下水疏通 / 报警器电池 / 水电）、续约费、90 / 60 / 30 天提醒日（自动）、搬出日、押金退还截止（自动 = 搬出日 + 21 天） |
| **询盘看房** | 物业编号、姓名、联系方式、来源平台、首次联系日、看房日期时间、已看房、反馈（只记对房子的看法）、意向度（热 / 温 / 冷）、下次跟进日、状态 |
| **申请人** | 物业编号、申请编号（名字缩写）、收到完整申请时间、材料完整、收入倍数、信用 vs 标准、租房历史、身份 / 雇主核实、符合标准、状态、决定日期、书面理由 |
| **维修工单** | 工单号、物业编号、报修日期、问题、位置、分级（紧急 / 优先 / 常规）、应完成日（自动：紧急当天、优先 +3 天、常规 +14 天）、责任判断（业主 / 租客 / 待定）、师傅、报价、业主批准日期、派工日期、完成日期、租客确认、付款方式、金额、状态 |
| **租金记录** | 物业编号、月份、应收、实收、差额（自动，填了实收才算）、收款日期、迟交、滞纳金、租金流向、业主确认 / 信托入账、备注 |
| **账单** | 账单号、物业编号、业主、开票日期、类型（租赁费 / 管理费 / 续约费 / 维修协调费 / 其他）、金额、到期日、已付日期、状态（自动：已付 / 逾期 / 未付） |
| **待办提醒** | 日期、物业编号、事项、来源模块、优先级、状态 |
| **师傅名单** | 工种、名称、电话、邮箱、CSLB 执照号、保险、服务区域、评价、备注 |

- **审批上限、租金流向、维修付款**放在物业总览（属于托管合同，换租客也不变）。物业总览没填 → 用 M00 设置的默认值。
- **当前步骤**：在管的物业写最急的未完成事项所在的模块（比如有维修就写 M11）；没有特别事项写 M13。
- **待办提醒表只放人工事项**（比如「问业主持有方式」「HOA 门禁卡申请」）。下面第 4 节能从日期算出来的提醒（续约、交租、上市天数、工单、押金期限）**不要再抄进待办表**，避免重复。

**状态流程**
- 询盘：询盘 → 已约看 → 已看房 → 已申请 → 审核中 → 已选定 / 未选中 → 已签约
- 工单：报修 → 已分级 → 报价中 → 待批准 → 已派工 → 已完成 → 已付款 → 已归档
- 物业：评估中 → 签约中 → 接房 → 修缮 → 上市 → 筛选 → 签租约 → 已入住 → 在管 → 续约中 / 退租中 → 已结束

**意向度只看行为**：回复速度、有没有看房、有没有问申请问题、入住日期合不合适。不看对方是什么人。

## 4. 提醒规则

每次对话只查一次。范围：**已过期还没处理的**（先列）+ **今天到 7 天后（含）**到期的。

| 来源 | 提醒日期（从原始日期算） |
|---|---|
| 租约到期日（定期） | 到期日 − 90 / 60 / 30 天（天数按使用说明页 / M00）→ M14。**已经过了的提醒日但还没开始续约 → 列为「已过期」** |
| 月租的租约 | 没有到期日：每年起租周年前 90 天提醒检查涨租和条款 → M14 |
| 交租日 | 交租日前 X 天（M00，默认 3）；交租日当天没有实收记录；宽限期最后一天；滞纳金生效 → M12。**只检查当前月份和租金记录表里已有的月份**（总控台建立之前的月份不算欠租） |
| 押金退还 | 搬出日 + 21 天，每次都显示「剩 X 天」→ M15 |
| 签约后给租约副本 | 起租或签约后 15 天内（§1962）；新接手的物业 15 天内告知租客 → M09 / M03 |
| 上市天数 | 上市当天算**第 0 天**；第 7 / 14 / 21 天 → M06 调价规则 |
| 申请 | 完整申请超过 48 小时未处理 → M07 |
| 工单 | 过了「应完成日」还没完成 → M11 |
| 业主账单 | 过了到期日还没付 → M10 |
| 保险、HOA、许可证 | 业主提供的到期日前 30 天 |
| 定期检查 | 按租约条款 → M13 |
| 法规更新 | 每年 1 月 1 日（新法）、8 月 1 日（AB 1482 上限）；租控城市年度登记 → X3 |
| 待办提醒表 | 状态不是「完成 / 取消」、日期在范围内的 |

**输出格式**（最多 5 条，先过期后到期，按日期；更多的写「另有 N 条」）：
```
📋 待处理
⏰ 已过期：10/01 · 88 Elm Ave · 租约 60 天提醒（还没开始续约）→ 回复「做 1」
1. 10/27 · 88 Elm Ave · 工单 W-001 应完成 → 「做 2」
2. …
⚠️ 红线：{如有，一行}
```

## 5. 常用查询

- 「XX 地址到哪一步了」→ 物业总览的那一行 + 待办 + `记录.md` 最后 5 条
- 「这个房子的申请人对比」→ 申请人表按物业筛选，按收到完整申请的时间排序
- 「这周计划」→ 第 4 节的提醒 + 待办，排出每天做什么
- 「哪些房子空着」→ 状态为上市 / 筛选的物业 + 已上市天数（按上市日期现算）

## 6. 可选：每周定时检查

如果用户想要自动提醒，告诉用户可以在自己的 Claude 应用里建一个**定时任务**，例如：
「每周一早上 8 点：用 lease-strategist 读 租管数据/总控台.xlsx，列出本周到期和已过期的事项，以及红线警告。」
本 skill 不会自己在后台运行。
